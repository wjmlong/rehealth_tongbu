### 2.3 启动脚本如何取用

- `start-local-apps.ps1`：把 `provider_credential` 路径传给 `REHEALTH_LLM_API_KEY_FILE`、`vision_provider_credential` 传给 `REHEALTH_VISION_API_KEY_FILE`、`internal_service_credential` 传给内部令牌文件变量；Device Service 用 `REHEALTH_HARDWARE_DB_PASSWORD_FILE`。
- `start-local-insurance-backend.ps1`：从 `secrets/software_db_password`、`secrets/redis_password` 注入 JDBC/Redis 密码。
- 种子脚本（`seed-*.ps1`）：直接读 `secrets/software_db_password`、`secrets/hardware_db_password`。
- **结论**：本地启动必须走受管脚本；手动 `mvn spring-boot:run` 不带这些环境变量会导致健康问答/视觉分析不可用（`STATUS.md` 2026-08-24 记录过）。

### 2.4 阿里云短信/号码认证（Dypnsapi）

- **Key 位置**：`secrets/aliyun_sms_access_key_id` 与 `secrets/aliyun_sms_access_key_secret`（各一行）。
- **开关与签名**：`.env` 里 `JEECG_SMS_DEV_MODE=false`、`JEECG_SMS_DYPNS_ENABLED=true`、`JEECG_SMS_DYPNS_SIGN_NAME=<阿里云号码认证控制台显示的赠送签名>`。
- **模板约定**：登录/注册模板 `100001`，`TemplateParam {"code":"##code##","min":"5"}`；6 位码、5 分钟有效、60 秒冷却。
- **RAM 最小权限**：只授 `dypns:SendSmsVerifyCode` 和 `dypns:CheckSmsVerifyCode`；**不得复用 OSS AccessKey**；不得与标准短信服务 `Dysmsapi` 的签名/模板混用（旧 `JEECG_SMS_ALIYUN_*` 仅本地兼容回退）。
- **本地开发模式**：`JEECG_SMS_DEV_MODE=true` 时注册只接受固定验证码 `123456`，不调用网关，仍有服务端频控。
- **轮换**：换 Key 后重启 JeecgBoot（SDK 客户端在启动时构建）。

### 2.5 云米（Viomi）

- `.env` 填 `REHEALTH_VIOMI_APP_ID`、`REHEALTH_VIOMI_APP_KEY`（可加 `REHEALTH_VIOMI_USER_ID`）。
- 服务端主动测量另需 `REHEALTH_VIOMI_PLAN_ENCRYPTION_SECRET` + 三个命令码。
- **命令码默认关闭（`0`）**：必须等目标型号/固件通过厂商与物理设备验证后按环境变量启用；不要为“看起来能发命令”提前打开。
- App 端不持有任何云米凭据；凭据只在服务端 `.env`。

### 2.6 Nacos / Grafana / 代理

- 本地 Nacos 关闭鉴权（`NACOS_AUTH_ENABLE=false`），控制台 `http://localhost:8848/nacos` 默认 `nacos/nacos`。
- Grafana `http://localhost:3000`，admin 密码来自 `secrets/grafana_admin_password`。
- 需要代理访问外网 Provider 时用 §2.1 的 `REHEALTH_JEECG_HTTPS_PROXY_*`；代理密码一律不写任何配置文件。

### 6.2 填写与使用纪律

1. **secrets 文件格式**：一行一个值、无引号、无注释尾注；权限 owner-only（Linux 上 `0600`）。
2. **不打印**：AppKey、API Key、数据库密码不进入日志、终端回显、截图或本文档。
3. **不进 APK**：Provider/视觉/云米/短信凭据全部只存在于服务端；Android 只持有自己的 `JEECG_SIGNATURE_SECRET`（本地联调）与后端 URL。
4. **最小权限**：阿里云短信用专用 RAM 用户（只授两个 `dypns:*` 权限），不复用 OSS 凭据。
5. **轮换后重启**：阿里云 Key、数据库/Redis 密码改动后重启对应 Java 进程；数据库密码改动还需与容器 volume 内实际密码一致。
6. **空文件陷阱**：`provider_credential` 若变为 0 字节，健康问答与干预生成会 fail-closed（返回不可用，不产生 Mock 结果）；此前（2026-08-24）曾因此出现 `provider_unavailable`，现已填充并恢复。任何 secrets 文件被清空后都应立即回填并重启对应 Java 进程。
7. **QA 密码**：所有种子账号密码 `123456` 只用于本地非临床验收；`LOCAL_*_QA` 数据禁止进入 staging/production。
8. **本地开关不得上生产**：`JEECG_SMS_DEV_MODE=true`、`rehealth.runtime.mode=development`、`REHEALTH_INSURANCE_TENANT_MEMBERSHIP_DEV_SCOPE_ENABLED=true`、`REHEALTH_QA_SYNTHETIC_ATTRIBUTION_HISTORY_ENABLED=true` 均为本地/QA 开关，生产必须关闭。

### 6.3 生产差异（本地 ↔ staging/production）

| 项 | 本地 | staging/production |

| 短信 | `JEECG_SMS_DEV_MODE=true`，固定码 `123456` | `false` + DYPNS 开启 + 赠送签名必填 |
| Kafka | 明文，无 TLS secrets | 需要 `kafka_sasl_jaas_config` / `kafka_truststore.p12` / `kafka_truststore_password` |
